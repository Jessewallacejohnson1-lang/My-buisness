# DEBUG launch arguments

Extracted from CLAUDE.md 2026-09-04. All compile out in Release.
Read this file when you need a specific flag; CLAUDE.md points here.

> **Pruned 2026-09-17.** The strip-down deleted the Today feed modules, the Activities and
> Calendar features, and the map tab, and took their flags with them. Every flag below was
> checked against the source on that date. The dead ones are called out where their absence
> would otherwise read as a bug — a flag that stages a deleted view is worse than no flag,
> because it fails silently. `docs/GUTTING-LEDGER.md` records what went and how to get it back.

**DEBUG-only launch arguments** (for headless verification; all compile out in Release):

- **Shell and previews:** `-open-tab town|daily|business|you` — **`-open-tab map` is dead**, the map is no longer a tab; `-tab-cycle` steps forward through the bar every 1.4s, wrapping, so the tab motion can be recorded headlessly (there is no tap automation here); `-open-map` raises the map cover on launch and is now the only headless way into the map, since the real entry is a tap on Today's top-bar map button; `-show-home`; `-show-loader`; `-show-loading-cover`; `-show-skeletons`; `-show-map-intro`; `-share-demo`; `-open-speeddial`, plus `-speeddial-loop`. The launch splash and its `-launch-splash-hold` / `-launch-splash-skip` flags were deleted on 2026-09-18: `LaunchScreen.storyboard` is bare paper now, so there is nothing to hold or skip. Note that `daily` and `business` open a `BlankTab` placeholder — the slot's name and its promise line. That is the correct result, not a failed launch. The social feed lives on **`town`**, inside `FeedView`'s scroll under `TodayTopBar` (fixtures in DEBUG, the empty state in release — there is no backend for it yet).
- **Today:** `-briefing-preview [-briefing-state sample|one_event|zero_events|voted|none|degraded]` mounts the real Today composition from a canned payload with no auth/network. **The payload still loads and the states still resolve, but the registry is empty**, so what you photograph is `TodayTopBar` over an empty feed — the flag now verifies the chrome and the read contract, not module layout. `-header-hairline` forces the scrolled header state; `-feed-render-log` prints every body re-evaluation of the feed layers (`Self._printChanges`); `-frame-gap-log` counts dropped display frames via CADisplayLink — the sim substitute for Instruments' Animation Hitches, which refuses the simulator platform. Two more still compile but have nothing to act on with an empty registry: `-feed-focus <moduleID>`, which hid the modules above the one being inspected, and the `-trivia-sample|-trivia-answered|-trivia-streak|-trivia-low-sample` fixtures, which `TriviaModel` still parses although its card is deleted. **Dead with their views:** `-briefing-gallery`, `-gallery-state`, `-feed-gallery`, `-feed-state`, `-townnotes-gallery`, `-townnotes-gallery-page`, `-foryou-sample`, `-foryou-no-tags`, `-foryou-empty`, and the almanac family (`-almanac-write|-almanac-static|-almanac-fail`, `-almanac-part`, `-almanac-demo-line`). The legacy card feed remains available for regression work via `-feed-card-gallery`, `-feed-card-autoplay`, and `-today-feed-preview|-today-feed-empty|-today-feed-skeleton`.
- **The Horizon layer (parked) and the Day Schedule sheet:** the Your Day section that used to carry the HORIZON CARD is deleted from Today, but the card's **pure layer survives intact and tested** under `Features/Home/Feed/Modules/Horizon/` — the solar model (`SolarSky`, `SolarTable`), the time axis, `HorizonDay`, the palette, the backdrop, `ScrubModel`/`ScrubHaptics`, and `HorizonCard` itself. It is unmounted on purpose, and the two galleries are now its **only** live entry point: `-horizon-sky-gallery` renders the sky, horizon line, solar dots and flat ground at the eight spec test times (no rail, no stubs, no text), and `-horizon-card-gallery` renders the full card over the `.busy` fixture at those same times; pair either with `-horizon-sky-gallery-page 2` for the afternoon/night half. Both galleries hard-code their own clock (sunrise 06:13, sunset 21:02) rather than reading a flag. **Compiled but no longer usable:** `-horizon-scrub-demo` and `-horizon-scrub-demo-script tour|sunset|fullday|events|empty|stress`, and `-horizon-a11y-demo`, still live inside `HorizonCard` and still fire from the gallery's cards, but the gallery hands each card `scrub: .constant(nil)`, so a demo session writes nowhere and nothing moves — they need a host with a real `scrub` binding before they mean anything again. The mock lane `-BPMockNow "<ISO8601>"` / `-BPMockSunTimes "HH:mm,HH:mm"` / `-BPMockDayState <state>` / `-BPMockNowSpeed <x>` is in the same position: `HorizonMock` still parses all four into `launchOverride`, but **nothing reads it any more** — the module that did is gone. `HorizonMock.items(for:day:)` itself is live and is what the card gallery draws. The flag strings do still do one real job: `DayCompletionStore` treats them as fixture markers and refuses to write a tick through to `club_events` under any of them. **Deleted outright:** `-horizon-press-card` and `-horizon-press-seeall` (their buttons are gone), and the rail staging flags `-yourday-sample|-yourday-loading|-yourday-error|-yourday-empty`, `-yourday-count <n>`, `-yourday-open-detail`, `-yourday-rail-end`, `-yourday-open-add`, `-yourday-open-explore`. The sheet is unchanged and is now reachable **only** by flag, since the rail that opened it is gone: `-day-sheet-preview [-day-sheet-state upcoming|inprogress|completed|empty|cta]`; `-day-sheet-hold` opens it once and stays; `-day-sheet-demo` loops open → scroll → tick → dismiss. Pair sheet flags with `-show-home` for the real tab shell. **Note:** `record_sim_video` fails in this setup (it starts, then can't report the output path) — use `xcrun simctl io <udid> recordVideo` instead.
- **The social feed (on Town):** `-daily-feed-preview [-daily-feed-state mixed|postings|events|empty]` mounts `DailyView` over `DailyFixtures` with no auth and no network. The state argument is not a convenience: nothing here can drive a scroll, so without it only whatever `DailyRanker` puts first is ever reachable for a screenshot — `postings` brings a 4:5 posting card to the top, `events` the short overlay card, `empty` the onboarding state. This flag mounts the column full-screen with no top bar; to photograph it where it actually ships, use `-open-tab town`. The ranked order is deliberate and worth checking against `DailyRankerTests`: tonight's event should outrank next month's, a finished event should be absent entirely, and a stranger's post that many of your follows thumbed should sit above a friend's that none did. Fixture content is INVENTED; only the town is real.
- **Utility row (parked):** `-utility-row-preview` renders the row full-screen, bypassing the auth gate; `-utility-expand|-utility-customize|-utility-empty` stage its states. The subsystem moved to `Features/Civic/Parked/Utility/` and is unreferenced on purpose, waiting on the Civic tab — these flags are how you confirm it still works before wiring it back in. See `Features/Civic/Parked/README.md`.
- **Map browsing and camera:** `-map-sheet places`; `-map-detent peek|medium|full`; `-map-open <spotid>` (`downtown|saintbens|chapel|wobegon|millstream|saintjohns`); `-map-open-poi [name-substring|id]`; `-map-detail-expanded` (with either open flag — starts straight in the full-details presentation the "View full details" row opens); `-map-filter all|food|parks|events|saved` starts the map on a chip; `-map-center <lat>,<lon>`; `-map-zoom <z>`; `-map-bearing <deg>`; `-map-pitch <deg>`; `-map-autozoom`. These now land inside a full-screen cover rather than a tab — the map carries its own close "X" leading in the top chrome, and `-open-map` is what raises it.
- **Map search:** `-map-search-open` expands the search field on appear (keyboard up); `-map-search <q>` also types the query so the results panel renders; `-map-search-committed <q>` programmatically commits the first result — fly + pin open (retries briefly while POIs load).
- **Signed-out data:** `-anon-data` — with NO session, `AuthStore.validAccessToken()` hands back the shipped public anon key so a signed-out simulator can still photograph data-bearing states. Reads go exactly as far as RLS lets the anon role (`places`/`club_events` allow anon SELECT); any write is refused server-side like any anonymous caller. DEBUG-only, compiles out in release.
- **Map marker/rain states:** repeatable `-map-save <spotid>` and `-map-force-live <spotid>`; `-town-rain` drives the real map interaction; `-town-rain-preview` bypasses auth and loops the physics; add `-poi-logo-stub` for deterministic offline logos. See `docs/town-rain-reference-measurements.md`.
- **Town menu/profile:** `-open-menu` with optional `-menu-autoclose` — the only entry into the menu since Today's avatar was removed on 2026-09-18, which also killed `-tap-menu` and `-slow-tap`; `-open-profile` with `-profile-expand|-profile-bottom|-profile-edit|-profile-edit-interests|-profile-moderation|-profile-autoclose`.
- **Appearance switch** (the town menu's System/Light/Dark control, which has no tap automation): `-appearance system|light|dark` makes the same persisted write a tap makes — relaunch WITHOUT the flag to prove it stuck; `-appearance-demo` (pair with `-open-menu`) walks the three states on a timer so the live, no-relaunch repaint can be recorded.
- **Onboarding:** none left. The signed-in wizard, the 20-screen pre-auth flow, the component bench and the motion bench were deleted on 2026-09-18, and every `-show-onboarding` / `-onboarding-*` / `-bp-*` flag went with them.
- **Data mutation:** `-seed-places` runs the DEBUG place seeder. Treat it as a backend write, not a harmless screenshot flag.
